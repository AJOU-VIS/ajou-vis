# 치토 목소리 합성 실험 (10/6)

- 담당: 진주영 (합성·목소리)
- 목적: Colab 음성 테스트에서 들린 목소리 문제의 원인을 가르고, 말투 지시·문장 사이 쉼 설정을 정한다.

---

## 1. 배경 — 음성 테스트(10/6, Opus)에서 들린 문제

1. 문장과 문장 사이 쉼이 짧다.
2. 반대로 쉼표에서는 길게 쉰다 — 마침표보다 쉼표가 더 길게 쉬어 어색하다.
3. "일반대학원은 당해학기 평점평균 2.5 ……… 미만일 때"처럼 숫자 뒤에서 길게 멈춘다.
4. 말이 느려서 답답하고, 답이 길다 (영어 답은 특히 김 — 프롬프트 쪽 문제로 따로 다룸).
5. "안녕하세요, 아주대 캠퍼스 안내 비서 치토예요!"까지는 빠르고 활기차다가, 다음 문장에서 갑자기 가라앉은 목소리가 된다.

## 2. 원인 분석 — 파이프라인 코드 확인 (speech-to-speech 포크)

- **문장 단위 합성**: LLM 답을 문장으로 잘라(`--stream_batch_sentences 1`) 문장마다 따로 합성한다(`--qwen3_tts_coalesce_inputs False`).
- **문장 앞 무음을 잘라낸다**: TTS가 매 발화 앞 무음을 0.04초만 남기고 자른다 → 문장 경계에는 앞 문장 끝 무음만 남아 쉼이 짧다(1). 쉼표 쉼은 한 번의 합성 안에서 모델이 만들기 때문에 문장 경계보다 길어질 수 있다(2).
- **문장마다 억양을 새로 뽑는다**: 따로 합성하므로 앞 문장의 분위기를 모른다(5).
- **속도 조절 옵션이 없다**: 말하기 속도는 말투 지시(instruct)에만 기댄다(4). TTS 샘플링 설정(`gen_kwargs`)은 GGML 경로에 전달되지 않아 지금은 조절할 수 없다.

## 3. 방법

고정 문장을 설정만 바꿔 합성하고 숫자와 청취로 비교했다 (대화로 테스트하면 LLM 답이 매번 달라 비교가 어렵다).

- 설정: 음성 서버와 같게 — Qwen3-TTS CustomVoice 1.7B, GGML Q8_0, 화자 Sohee, 문장 단위 합성. Colab GPU.
- 문장: 코퍼스(학칙·장학금 지급규칙·외국인학생 규칙)의 실제 내용으로 만든 8문장 — 짧은 인사, 보류, 가운뎃점 나열, 조항·숫자, 소수점, 학번·학점, 세 문장 긴 답, 영어.
- 측정
  - 초당 음절 수: 숫자 없는 문장의 한글 음절 수 ÷ 말소리 길이 (앞뒤 무음 제외)
  - 쉼: 가장 큰 소리보다 35dB 이상 작은 구간이 0.15초 이상 이어지면 쉼으로 셈
  - 문장 경계 쉼: 앞 문장 끝 무음 + 뒷 문장 앞 무음 (서버에서 실제로 들리는 쉼)
  - 문장 간 일관성: 둘째 문장의 음높이 하락(반음)·크기 하락(dB)
  - 청취 평가: 자연스러움 · 끊김 없음 · 속도 적절 · 숫자 발음 · 치토다움 (1~5)

| 실험 | 비교 조건 |
|---|---|
| 1. 말투 지시 | current(기존) / none(지시 없음) / brisk / steady × 8문장 |
| 2. 숫자 읽기 | 숫자 그대로(digits) vs 한글 읽기(spoken, 예: "이 점 오") — 3쌍 × 3회 |
| 3. 문장 사이 쉼 | 따로 합성 + 무음 0 / 0.3 / 0.5초, 두 문장 한 번에 합성 — 2쌍 × 3회 |
| 4. 문장 간 일관성 | current vs steady — 두 문장 인사 × 5회 |

말투 지시 원문:
- current: Bright, warm and friendly campus guide. Speak clearly at a natural, slightly upbeat pace with a cheerful, encouraging tone.
- brisk: Bright, warm and friendly campus guide. Speak clearly at a brisk, slightly fast pace with a cheerful, confident tone.
- steady: Bright, warm and friendly campus guide. Speak at a brisk, steady pace and keep the same bright, energetic tone from the first sentence to the last.

실험 노트북은 일회성이라 레포에 두지 않았다. 다시 할 때는 이 절의 조건대로 구성한다.

## 4. 결과 (청취 평가 기준)

| 실험 | 가장 나은 조건 |
|---|---|
| 1. 말투 지시 | **brisk / steady** — 기존(current)보다 덜 답답함 |
| 2. 숫자 읽기 | **숫자 그대로** — 한글 읽기로 바꾼 쪽이 더 낫지 않았음 |
| 3. 문장 사이 쉼 | **따로 합성 + 0.4초 무음**, 또는 두 문장 한 번에 합성 |
| 4. 문장 간 일관성 | **steady** |

측정값 (실험 결과 zip의 CSV에서 옮겨 적을 것 — 아직 미기입):

| 지표 | current | brisk | steady |
|---|---|---|---|
| 초당 음절 수 (숫자 없는 문장 평균) | | | |
| 둘째 문장 음높이 하락 (반음, 평균) | | — | |
| 둘째 문장 크기 하락 (dB, 평균) | | — | |

## 5. 결정과 반영

| 결정 | 이유 | 반영 위치 |
|---|---|---|
| 말투 지시 → **steady** | 속도(실험 1)와 문장 간 일관성(실험 4) 둘 다 가장 나음 | `prompts/persona_ko.md` 목소리 블록, `server/colab_voice_server.ipynb` 1번 셀 `TTS_INSTRUCT` |
| 문장 사이 **0.4초 무음** | 쉼의 위계(문장 경계 > 쉼표)를 되돌림. "한 번에 합성"은 LLM이 둘째 문장까지 만들어야 첫 소리가 나와 지연이 늘고, 긴 입력에서 늘어짐 문제 이력이 있어 택하지 않음 (실시간성 우선) | 포크에 `--qwen3_tts_sentence_pause_s` 옵션 추가(브랜치 `feat/tts-sentence-pause`, 기본 0 = 기존과 동일) · Colab 1번 셀 `SENTENCE_PAUSE_S = 0.4`, 7번 셀은 포크에 옵션이 있을 때만 전달 |
| 숫자는 **그대로** | 한글 읽기 변환이 청취상 낫지 않음 → 텍스트 정규화 단계는 만들지 않음 | 변경 없음 |

## 6. 남은 것

- 대화 테스트에서 들린 "2.5 뒤 긴 멈춤"의 원인은 아직 확인 못 함 (고정 문장 실험에서는 숫자 변환이 해법이 아니었음) → 다음 음성 테스트에서 재현되는지 관찰.
- 답변 목표 길이 다시 정하기: steady의 초당 음절 수 × 허용 발화 시간 → 프롬프트 길이 규칙에 반영.
- 반영 확인: steady + 0.4초로 Colab 음성 테스트 (포크 옵션 PR 병합 후).
- 문장 간 일관성 추가 개선: 스피커 임베딩(참고 음성으로 목소리 고정, 포크에 `--qwen3_tts_ref_audio` 등 옵션 있음), TTS 샘플링 조절(GGML 경로에 `gen_kwargs` 전달 — 코드 수정 필요, 다혜 님과).
