# 치토 목소리 합성 실험 (1차 10/6 · 2차 10/27)

- 담당: 진주영 (합성·목소리)
- 목적: Colab 음성 테스트에서 들린 목소리 문제의 원인을 가르고, 말투 지시·문장 사이 쉼 설정을 정한다.
- 1차(1~6절): 말투 지시 steady, 문장 사이 0.4초 채택. 2차(7절): 말투가 문장마다 바뀌는 문제가 남아 기준 음성 복제로 목소리를 고정 → 새 목소리(D) 채택.

---

## 1. 배경 — 음성 테스트(10/6, Opus)에서 들린 문제

1. 문장과 문장 사이 쉼이 짧다.
2. 반대로 쉼표에서는 길게 쉰다 — 마침표보다 쉼표가 더 길게 쉬어 어색하다.
3. "일반대학원은 당해학기 평점평균 2.5 ……… 미만일 때"처럼 숫자 뒤에서 길게 멈춘다.
4. 말이 느려서 답답하고, 답이 길다 (영어 답은 특히 김 — 프롬프트 쪽 문제로 따로 다룸).
5. "안녕하세요, 아주대 캠퍼스 안내 비서 치토예요!"까지는 빠르고 활기차다가, 다음 문장에서 갑자기 가라앉은 목소리가 된다.

## 2. 원인 분석 — 파이프라인 코드 확인 (speech-to-speech 포크)

- **문장 단위 합성**: LLM 답을 문장으로 잘라(`--stream_batch_sentences 1`) 문장마다 따로 합성한다(`--qwen3_tts_coalesce_inputs False`).
- **문장 앞 무음을 잘라낸다**: TTS가 매 발화 앞 무음을 0.04초만 남기고 자른다 → 문장 경계에는 앞 문장 끝 무음만 남아 쉼이 짧다(1). 쉼표 쉼은 한 번의 합성 안에서 모델이 만들기 때문에 문장 경계보다 길어질 수 있다(2).
- **문장마다 억양을 새로 뽑는다**: 따로 합성하므로 앞 문장의 분위기를 모른다(5).
- **속도 조절 옵션이 없다**: 말하기 속도는 말투 지시(instruct)에만 기댄다(4). TTS 샘플링 설정(`gen_kwargs`)은 GGML 경로에 전달되지 않아 지금은 조절할 수 없다.

## 3. 방법

고정 문장을 설정만 바꿔 합성하고 숫자와 청취로 비교했다 (대화로 테스트하면 LLM 답이 매번 달라 비교가 어렵다).

- 설정: 음성 서버와 같게 — Qwen3-TTS CustomVoice 1.7B, GGML Q8_0, 화자 Sohee, 문장 단위 합성. Colab GPU.
- 문장: 코퍼스(학칙·장학금 지급규칙·외국인학생 규칙)의 실제 내용으로 만든 8문장 — 짧은 인사, 보류, 가운뎃점 나열, 조항·숫자, 소수점, 학번·학점, 세 문장 긴 답, 영어.
- 측정
  - 초당 음절 수: 숫자 없는 문장의 한글 음절 수 ÷ 말소리 길이 (앞뒤 무음 제외)
  - 쉼: 가장 큰 소리보다 35dB 이상 작은 구간이 0.15초 이상 이어지면 쉼으로 셈
  - 문장 경계 쉼: 앞 문장 끝 무음 + 뒷 문장 앞 무음 (서버에서 실제로 들리는 쉼)
  - 문장 간 일관성: 둘째 문장의 음높이 하락(반음)·크기 하락(dB)
  - 청취 평가: 자연스러움 · 끊김 없음 · 속도 적절 · 숫자 발음 · 치토다움 (1~5)

| 실험 | 비교 조건 |
|---|---|
| 1. 말투 지시 | current(기존) / none(지시 없음) / brisk / steady × 8문장 |
| 2. 숫자 읽기 | 숫자 그대로(digits) vs 한글 읽기(spoken, 예: "이 점 오") — 3쌍 × 3회 |
| 3. 문장 사이 쉼 | 따로 합성 + 무음 0 / 0.3 / 0.5초, 두 문장 한 번에 합성 — 2쌍 × 3회 |
| 4. 문장 간 일관성 | current vs steady — 두 문장 인사 × 5회 |

말투 지시 원문:
- current: Bright, warm and friendly campus guide. Speak clearly at a natural, slightly upbeat pace with a cheerful, encouraging tone.
- brisk: Bright, warm and friendly campus guide. Speak clearly at a brisk, slightly fast pace with a cheerful, confident tone.
- steady: Bright, warm and friendly campus guide. Speak at a brisk, steady pace and keep the same bright, energetic tone from the first sentence to the last.

실험 노트북은 일회성이라 레포에 두지 않았다. 다시 할 때는 이 절의 조건대로 구성한다.

## 4. 결과 (청취 평가 기준)

| 실험 | 가장 나은 조건 |
|---|---|
| 1. 말투 지시 | **brisk / steady** — 기존(current)보다 덜 답답함 |
| 2. 숫자 읽기 | **숫자 그대로** — 한글 읽기로 바꾼 쪽이 더 낫지 않았음 |
| 3. 문장 사이 쉼 | **따로 합성 + 0.4초 무음**, 또는 두 문장 한 번에 합성 |
| 4. 문장 간 일관성 | **steady** |

| 초당 음절 수 (숫자 없는 문장 평균) | | | |
| 둘째 문장 음높이 하락 (반음, 평균) | | — | |

## 5. 결정과 반영

| 결정 | 이유 | 반영 위치 |
|---|---|---|
| 말투 지시 → **steady** | 속도(실험 1)와 문장 간 일관성(실험 4) 둘 다 가장 나음 | `prompts/persona_ko.md` 목소리 블록, `server/colab_voice_server.ipynb` 1번 셀 `TTS_INSTRUCT` |
| 문장 사이 **0.4초 무음** | 쉼의 위계(문장 경계 > 쉼표)를 되돌림. "한 번에 합성"은 LLM이 둘째 문장까지 만들어야 첫 소리가 나와 지연이 늘고, 긴 입력에서 늘어짐 문제 이력이 있어 택하지 않음 (실시간성 우선) | 포크에 `--qwen3_tts_sentence_pause_s` 옵션 추가(브랜치 `feat/tts-sentence-pause`, 기본 0 = 기존과 동일) · Colab 1번 셀 `SENTENCE_PAUSE_S = 0.4`, 7번 셀은 포크에 옵션이 있을 때만 전달 |
| 숫자는 **그대로** | 한글 읽기 변환이 청취상 낫지 않음 → 텍스트 정규화 단계는 만들지 않음 | 변경 없음 |

## 6. 남은 것

- 대화 테스트에서 들린 "2.5 뒤 긴 멈춤"의 원인은 아직 확인 못 함 (고정 문장 실험에서는 숫자 변환이 해법이 아니었음) → 다음 음성 테스트에서 재현되는지 관찰.
- 답변 목표 길이 다시 정하기: steady의 초당 음절 수 × 허용 발화 시간 → 프롬프트 길이 규칙에 반영.
  → 10/27: 목표를 약 12초(2문장, 80자 안팎)로 정함. 2차에서 채택한 목소리가 초당 약 6.1음절이라 12초 ≈ 73음절. 프롬프트 v1.4b에 반영 예정.
- 반영 확인: steady + 0.4초로 Colab 음성 테스트 (포크 옵션 PR 병합 후).
  → 10/27 음성 테스트: 0.4초 쉼은 해결 확인. 문장마다 말투가 바뀌는 문제는 남음 → 2차 실험.
- 문장 간 일관성 추가 개선: 스피커 임베딩(참고 음성으로 목소리 고정, 포크에 `--qwen3_tts_ref_audio` 등 옵션 있음), TTS 샘플링 조절(GGML 경로에 `gen_kwargs` 전달 — 코드 수정 필요, 다혜 님과).
  → 참고 음성으로 목소리 고정은 2차 실험에서 확인하고 채택 (7절). 샘플링 조절은 하지 않음.

## 7. 2차 실험 (10/27): 목소리 고정

### 7.1 배경: 10/27 음성 테스트에서 들린 문제

steady + 0.4초를 반영한 뒤 Colab 음성 테스트를 다시 했다 (이번 테스트는 LLM이 Haiku였음 — 답 내용 문제는 프롬프트 쪽에서 따로 다룸).

1. 목소리가 우울하고 어색하게(불쾌한 골짜기처럼) 들린다.
2. steady로 바꿨는데도 문장마다 말투(어조)가 달라진다.
3. 말이 아직 느리다: 답변 음성의 초당 음절 수 약 5.4 (4.6~6.3).
4. 문장 사이가 짧던 문제는 0.4초로 해결됐다.

### 7.2 방법

1차와 같이 고정 문장을 설정만 바꿔 합성하고, 측정값과 청취로 비교했다.

- 설정: 음성 서버와 같게 — Qwen3-TTS 1.7B, GGML Q8_0, 문장마다 따로 합성, 문장 사이 0.4초. 합성 결과도 서버(`qwen3_tts_handler`)와 같게 조각마다 16kHz로 바꾸고 앞 무음을 자름. Colab T4.
- 문장: 10/27 음성 테스트의 실제 답 6개를 v1.4b 말투(해요체·괄호 없음·2문장)로 고친 것 — 인사, 편의점(CU·층), 휴학(숫자 없음), 졸업학점(학번·"2.0"), 셔틀(시각·출구 번호), 영어. 내용은 합성 비교용이다.
- 조건마다 문장당 3회 합성 → 측정값은 3회 평균, 청취는 첫 번째 합성.

| 조건 | 내용 |
|---|---|
| A | 지금 서버 설정: 소희 + steady 지시문 (CustomVoice) |
| B1 | 소희 + 대화체 지시문 (영어): "친한 친구와 이야기하듯, 목소리에 미소를 담아 경쾌하게, 모든 문장을 같은 톤으로" |
| B2 | 소희 + B1과 같은 뜻의 한국어 지시문 |
| C | 소희 목소리 고정: 소희가 말한 기준 음성 1개로 모든 문장을 복제 (Base, ICL) |
| D | 새 목소리 고정: 목소리 설계 모델(VoiceDesign)로 만든 기준 음성 1개로 모든 문장을 복제 (Base, ICL) |

- 기준 음성: 같은 문장(약 10초, "반가워요! 저는 학교생활을 도와주는 안내 비서예요. …")으로 후보를 만들고 주영이 듣고 골랐다.
  - C: 소희 후보 6개(지시문 A·B1·B2 × 2) 중 `소희_A_1`.
  - D: 목소리 설계 후보 4개 중 `설계_3`. 설계 설명은 "A bright, friendly Korean woman in her early twenties working as a campus guide. Clear, warm voice with a gentle smile, natural conversational intonation, and a lively, slightly quick pace."
- 청취 평가: 주영 1명, 조건 이름을 가리고 문장마다 무작위 번호로 들음 (블라인드).
  - 항목: 밝기 · 자연스러움 · 일관성(문장 간 톤 유지) · 속도. 1~5점이고 **5 = 매우 좋음**(매우 적절한 밝기·속도, 매우 자연스러움, 매우 일관됨).
  - 실험 노트북 안내에는 속도를 "3 = 딱 좋음"으로 잘못 적었다. 실제 채점은 5 = 매우 적절로 했으므로 아래 표는 그 기준으로 다시 계산했다. 순위와 속도 비교 대상(상위 2개)은 어느 기준이든 같다.
- 측정: 1차와 같은 초당 음절 수(숫자·영어 없는 한국어 문장)·둘째 문장 음높이 하락에, 첫 소리까지 시간(TTFA)과 RTF(생성 속도 ÷ 실시간)를 더함.
- 2단계 속도: 1단계 상위 2개(D, C)에 재생 속도 1.0 / 1.1 / 1.15 / 1.2배(rubberband, 음높이 유지)를 적용. 기준 음성 자체를 1.15배 빠르게 해서 복제한 것("빠른 참고")도 비교. 문장 3개(인사·휴학·졸업학점)로 진행.
- 부록: 같은 합성 결과(D)를 서버 방식(조각마다 16kHz 변환) / 한 번에 16kHz 변환 / 24kHz 원본으로 들어 봄. 문장 2개(인사·휴학)로 진행.

실험 노트북과 결과(점수·측정값 CSV, 음성 파일)는 1차와 같이 레포에 두지 않았다.

### 7.3 결과

**1단계: 목소리·말투** (청취 점수는 6문장 평균, 종합 = 4항목 평균)

| 조건 | 밝기 | 자연스러움 | 일관성 | 속도 | 종합 | 초당 음절 | 둘째 문장 음높이 하락(반음) | 첫 소리까지(초) | RTF |
|---|---|---|---|---|---|---|---|---|---|
| **D** 새 목소리 고정 | **4.67** | 3.67 | **4.67** | **5.00** | **4.50** | 6.09 | 2.30 | 0.22 | 2.88 |
| C 소희 고정 | 4.17 | **4.33** | 4.50 | 4.67 | 4.42 | 6.15 | 0.65 | 0.22 | 2.93 |
| A 지금 설정 (steady) | 4.00 | 2.83 | 2.83 | 4.17 | 3.46 | 5.88 | 2.24 | 0.20 | 3.19 |
| B1 대화체 지시 (영어) | 3.67 | 3.00 | 3.33 | 3.83 | 3.46 | 5.45 | 0.89 | 0.20 | 3.15 |
| B2 대화체 지시 (한국어) | 3.33 | 2.67 | 2.83 | 3.67 | 3.12 | 5.40 | 0.98 | 0.20 | 3.18 |

- **목소리를 기준 음성으로 고정한 C·D가 네 항목 모두에서 지시문만 쓴 A·B1·B2보다 높다.** 특히 일관성이 4.5 이상(A·B는 2.8~3.3)이라, 문장마다 말투가 바뀌는 문제가 해결된다.
- 지시문만 바꾸는 방법(B1·B2)은 효과가 없었다. 점수는 A와 같거나 낮고 오히려 느려졌다(초당 5.4음절). 한국어 지시문(B2)이 가장 낮았다.
- 지연은 그대로다. 첫 소리까지 0.20~0.22초로 같고, RTF는 약 2.9로 조금 낮지만 실시간보다 3배 가까이 빠르다.
- D와 C의 차이(종합 4.50 vs 4.42)는 청취자 1명·6문장 기준이라 크지 않다. D는 밝기·속도가, C는 자연스러움이 높았다.
- 측정한 "둘째 문장 음높이 하락"은 청취 일관성과 맞지 않았다 (D는 2.3반음 하락인데 일관성 4.67). 평서문 끝이 자연스럽게 내려가는 것까지 섞이는 것으로 보여, 일관성은 청취 점수로 판단했다.

**2단계: 속도** (문장 3개 평균. 배율 행의 초당 음절은 원래 속도 × 배율로 계산)

| 조건 | 자연스러움 | 속도 | 초당 음절 |
|---|---|---|---|
| **D 원래 속도** | **5.00** | **5.00** | 6.24 |
| D ×1.1 | 4.00 | 4.67 | 6.86 |
| D ×1.15 | 3.67 | 4.00 | 7.17 |
| D ×1.2 | 3.33 | 3.33 | 7.49 |
| D 빠른 참고 | 4.33 | 4.33 | 6.84 |
| C 원래 속도 | 4.00 | 4.33 | 6.03 |
| C ×1.1 | 2.67 | 4.33 | 6.63 |
| C ×1.15 | 2.67 | 4.33 | 6.94 |
| C ×1.2 | 2.67 | 4.00 | 7.24 |
| C 빠른 참고 | 3.67 | 4.00 | 6.99 |

- 고정한 목소리는 **원래 속도가 가장 좋았다** (D 원래 속도: 초당 약 6.2음절, 자연스러움·속도 모두 5점). 지금 설정(A)보다 이미 빠르다.
- 합성 후 빠르게 하면 자연스러움이 떨어지고(C는 1.1배부터 2.67), 기준 음성을 빠르게 한 복제도 원래 속도보다 낮았다 → 속도 후처리는 넣지 않는다.

**부록: 서버 후처리** (D, 문장 2개)

| 처리 | 맑음 | 자연스러움 |
|---|---|---|
| 24kHz 원본 | **5.0** | 5.0 |
| 한 번에 16kHz 변환 | 4.0 | 5.0 |
| 서버 방식 (조각마다 16kHz 변환) | 3.5 | 5.0 |

- 서버가 24kHz 합성 결과를 16kHz로 낮춰 보내는 것이 맑음을 떨어뜨린다 (문장 2개라 근거는 약함). 우울하게 들리던 원인 중 하나일 수 있다.

**청취 메모**

- 숫자 읽기 (셔틀 문장 "9번과 10번 출구"): D는 9번을 "아홉 번", A는 10번을 "열 번"으로 읽었고, C는 9번을 알아듣기 어렵게 읽었다. "2.0"은 모든 조건이 맞게 읽었다.
- 영어 (Seongho·Ilsin·Paldal): A·B1·B2는 "Seongho"를 "시응호"로 읽었다. A·B2는 콩글리시 느낌이 났고 D는 조금 났다. B1은 둘째 문장부터 느려지고 Ilsin·Paldal을 제대로 못 읽었다. C는 메모 없음.

### 7.4 결정과 반영

블라인드 결과를 본 뒤 C·D를 이름을 공개하고 다시 들어 주영이 D로 결정했다 (10/27). 숫자 읽기 오류("아홉 번")는 있지만 목소리 자체는 D가 낫다고 판단했다.

| 결정 | 이유 | 반영 위치 |
|---|---|---|
| 목소리 → **D (기준 음성 `설계_3` 복제)** | 종합 1위. 일관성·밝기·속도가 가장 높고 지연은 그대로 | 기준 음성 `chito_ref.wav`(팀 Drive, Colab 3번 셀에서 올림), `prompts/persona_ko.md` 목소리 블록(페르소나 v2.2), `server/colab_voice_server.ipynb` 1·3·7번 셀 (`TTS_VOICE = "clone"`) |
| 말투 지시문은 쓰지 않음 | 지시문만 바꾸는 방법은 효과가 없었고, 복제에서는 기준 음성이 말투를 정함 | Colab 1번 셀 (`TTS_VOICE = "custom"`으로 되돌릴 때만 사용) |
| 속도 후처리는 넣지 않음 | 고정한 목소리의 원래 속도(초당 약 6.1~6.2음절)가 가장 좋음 | 변경 없음 |
| 복제할 때도 문장마다 언어를 넘김 | 서버의 복제 경로는 언어를 `auto`로 넘기는데 실험은 문장마다 korean/english를 넘겼음 → 실험과 같게 맞춤. 언어는 합성할 문장의 글자(한글·영문)로 먼저 정하고, 판단이 안 되면 사용자 발화 언어를 씀 (7.5) | 포크 `qwen3_tts_handler` (브랜치 `fix/tts-clone-language`) |

### 7.5 반영 확인: Colab 대화 테스트 (10/27, Opus)

브랜치 `feat/voice-d`(ajou-vis) + `fix/tts-clone-language`(포크)로 실행했다.

- 목소리: D 목소리로 합성됨 (로그 `voice_clone`). 주영 청취로 좋음. TTS 첫 소리까지 0.10~0.16초, RTF 5.3~7.0.
- 답 내용: CU("CU 편의점"이라고 말했을 때)·휴학·학사경고(한·영) 모두 정확하고 해요체를 지킴.
- 문제 1: "9번 출구"를 여전히 "아홉 번"으로 읽음 → 인공지능 과목 과제로 넘김 (7.6).
- 문제 2: 한국어로 "방금 거 영어로 답해 줘"라고 하자 영어 답이 콩글리시로 읽히고 숫자도 한국어로 읽힘.
  - 원인: 포크 수정이 사용자 발화 언어(ko)를 넘겨, 영어 답을 한국어 모드로 합성함.
  - 수정: 합성할 문장의 글자로 언어를 먼저 정하게 고침 (같은 포크 브랜치, 테스트 추가). 대화 테스트로 다시 확인할 것.
- 음성 인식 문제 (다혜 님 담당):
  - "CU"를 "씨유"로 받아 적어 검색 점수가 0.44~0.47로 기준(0.5)에 못 미쳐 보류 문장이 나감. "CU"로 적으면 0.75.
  - "수원역"을 "소원역"으로 받아 적음.
  - 말을 시작하기 전에 아이슬란드어·일본어로 받아 적음 ("Hrækki", "学校アーネス" 등).
- 지연: 발화 종료부터 첫 오디오까지 평균 5.6초(9턴)이고 대부분 LLM(Opus) 시간이다. "소원역" 질문은 LLM이 13초 걸림.
