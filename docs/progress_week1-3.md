# AJOU-VIS 진행 브리핑 (1~3주차, 9/1 ~ 9/21)

## 한 줄 요약

huggingface/speech-to-speech 레포를 포크해 개발 기반을 확정했고, 자체 벤치마크를 거쳐 **한국어 STT는 whisper-large-v3-turbo, TTS는 Qwen3-TTS Q8_0 양자화**를 데이터 근거와 함께 선정했다 (TTS는 팀 청취 평가만 남음). 프롬프트 v1과 캐릭터 설정도 완성되어 파이프라인 통합 단계로 넘어간다.

## 1. 개발 환경 구축 (1주차)

- 팀 GitHub 조직 **AJOU-VIS** 생성, 메인 레포에 모듈별 디렉토리 구조 확정 (server / corpus / prompts / eval / bench / client / docs)
- 저장소 관리 정책 수립 — 민감정보·캐릭터 에셋(홍보실 협약)·음성 데이터는 레포 제외, Drive 관리
- **참고 레포 분석 결과**: 목표 구조(VAD→STT→LLM→TTS)가 모듈식으로 구현되어 있고 Apache-2.0이라 포크 후 수정 전략 채택 → `AJOU-VIS/speech-to-speech` 포크 완료
  - LLM 슬롯이 OpenAI 호환 API 방식 → 자체 RAG 서버를 호환 엔드포인트로 만들면 무수정 연결 가능
  - socket 모드 지원 → 소형 보드 시제품에 경량 클라이언트만 탑재하는 구조 실현 가능
  - **기본 STT(Parakeet TDT)가 한국어 미지원** → 한국어 STT 벤치마크가 필수 과제임을 확인

## 2. 한국어 STT 벤치마크 → 모델 확정 (2주차, 이다혜)

자체 제작 Colab 벤치마크(`bench/stt_benchmark_colab.ipynb` — 레포 기본 스크립트가 한국어 설정 불가라 핸들러 직접 호출 방식으로 구현), 학사 도메인 자체 녹음 10문장, 한국어 CER(공백·구두점 제거 정규화) 기준.

| 모델 | CER | 문장당 추론 | GPU 메모리 |
|---|---|---|---|
| **whisper-large-v3-turbo** | **2.8%** | 0.26s | 1.8GB |
| faster-whisper-large-v3-turbo | 3.7% | 0.35s | 1.7GB |
| faster-whisper-medium | 5.7% | 0.38s | 1.7GB |
| qwen3-asr | 6.4% | 0.87s | 1.6GB |
| faster-whisper-small | 8.7% | 0.18s | 0.6GB |

**확정: whisper-large-v3-turbo** — 정확도·속도 동시 1위, RTF 0.06으로 실시간 요건 충족 (Tesla T4 측정, 원자료: `bench/results/stt_benchmark_*`)

## 3. Qwen3-TTS 양자화 벤치마크 (3주차, 이다혜)

치토가 실제 말할 문장 5종(인사·근거 인용·숫자·보류 응답·영어)으로 GGML 양자화 3종 비교 (`bench/tts_benchmark_colab.ipynb`).

| 양자화 | 합성 속도 | 첫 오디오까지(TTFC) | RTF | GPU 메모리 |
|---|---|---|---|---|
| BF16 | 3.66s | 0.20s | 2.2 | 5.0GB |
| **Q8_0** | **2.16s** | **0.09s** | **3.3** | **3.2GB** |
| Q4_K_M | GGML 백엔드 재현성 크래시(SIGABRT)로 제외 | | | |

**잠정 결론: Q8_0** — 모든 지표에서 BF16 우위(속도 1.7배, 지연 절반, 메모리 36% 절감). 합성 샘플을 Drive에 공유해 팀 전원 청취 평가 후 최종 확정 예정. (원자료: `bench/results/tts_benchmark_*`)

벤치마크 과정에서 GGML 네이티브 크래시로 Colab 커널이 반복 중단되는 문제를 **양자화별 프로세스 격리 + 체크포인트 저장** 구조로 해결.

## 4. 프롬프트·페르소나 v1 (진주영)

- **시스템 프롬프트 v1** (`prompts/system_ko.md`, `system_en.md`) — 핵심 설계: 검색결과에 있는 내용만 근거로 사용, 무근거 시 답변 생성 대신 담당 부서 안내, 근거 출처를 문장 앞쪽에 자연스럽게 표기(음성 출력 최적화), 개인정보 처리 금지
- **캐릭터 '치토' 설정서** (`prompts/persona_ko.md`, `persona_en.md`) — 횃불 유래 불꽃 캐릭터, "무엇을 말할지는 근거 규칙이, 어떻게 말할지는 페르소나가" 원칙으로 정확성과 캐릭터성 분리
- **평가 문항집 양식** (`eval/question_bank.xlsx`, 4개 영역 × 25문항 틀) 생성
- 팀 내 검토 완료 — 파이프라인 적용 전 결정할 구조 이슈(검색결과 주입 방식, 멀티턴 처리) 도출, 차기 회의 안건

## 5. 코퍼스·데이터 환경 (박태연)

- 수집 대상 문서 목록화(학사규정·행정절차·외국인 안내·캠퍼스 시설 4개 영역), ChromaDB+LangChain 환경 구성, 한국어 임베딩 모델 후보 조사 진행

## 6. 서빙 구성 전망

확정 모델 조합 기준: STT 1.8GB + TTS 3.2GB ≈ **5GB로 T4급 GPU 1장에 수용 가능**, 응답 지연은 STT 0.26s + TTS 첫 오디오 0.09s로 실시간 대화 요건 충족. LLM은 API 호출이라 GPU 부담 없음.
