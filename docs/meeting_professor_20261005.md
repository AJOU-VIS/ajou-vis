## 1. 교수님 피드백

### 1-1. 실시간성 (핵심)
- 음성 비서는 결국 "얼마나 빨리 답하냐"로 승부 → 실시간성에 포커스
- **STT**: Whisper는 실시간이 안 되니 Qwen3-ASR로 교체 검토 (단, 마지막에 "그냥 Whisper 써라"고 하신 것 같음 — 확인 필요)
- **TTS**: 답변이 길면 alignment 문제 발생 → 문장 단위로 잘라서 순차 생성
- **측정**: 한 토큰 생성에 몇 초 걸리는지 측정해서 "이만큼 빨라졌다"를 수치로 제시
- 참고: GPT realtime(실시간 음성 모델) 방향 언급

### 1-2. 시스템 역할 분리 (중요)
- [음성 인식 – LLM(Claude) – 음성 합성]을 인식/합성 둘로 나눠 역할 재분배
  - 인식팀: ASR을 빠르게 넘기기, 평가 기준("얼마나 빨라졌나") 정하기
  - 합성팀: 음성을 잘 합성하기, 목소리 일관되게 유지

### 1-3. TTS 음성 커스터마이징 (실험 과제)
- Voice design instruction / 스피커 임베딩 **둘 다** 해보기
- Instruction 예: 성별(중성적), 나이대, 감정 등 지정
- 커스텀 보이스로 치토 목소리 만들기

### 1-4. 개발·실험 방식
- Claude는 낮은 모델로 먼저 테스트, 시연 때 높은 모델 (비용·속도)
- Gradio로 데모 만들어 HuggingFace에 올리기
- 파인튜닝 조금이라도 해보기 — "AI 겉핥기로 하지 마라"
- 논문 보기 — 못 보더라도 관심은 가질 것

### 1-5. 차별성 (중요)
- 다른 AI 시스템 대비 차별성이 약할 수 있음 → "아주대만을 위한 게 있냐?"
- 답: **아주대 RAG 넣기 전후 비교** — 근거 없을 때(이상한 답) vs 넣었을 때(정확한 답)
- 26-2 최신 자료를 넣었다는 점도 강점

### 1-6. 발표 방식
- 가장 잘된 데모 하나만 보여주기
- 비교표 만들기 — Claude 버전별, 모델 버전별, RAG 전후 등

## 4. 확인할 점 · 제안

### 4-1. STT 교체 여부
2주차 벤치마크(Tesla T4, 자체 녹음 10문장):

| 모델 | CER | 문장당 처리 |
|---|---|---|
| whisper-large-v3-turbo | 2.8% | 0.26초 |
| Qwen3-ASR | 6.4% | 0.87초 |

교수님 말씀의 "실시간이 안 된다"는 처리 속도보다 **방식**(Whisper는 발화가 끝난 뒤 한 번에 인식, 스트리밍 ASR은 말하는 도중 인식)일 가능성이 있음. 어느 기준인지 교수님께 확인하고, 스트리밍 기준이면 "발화 종료 → 첫 인식 결과" 시간으로 재측정.

### 4-2. 파인튜닝 후보 (제안)
실제 로그에서 "휴학"이 "휴양", "추앙", "수학"으로 반복 오인식됨. 학사 용어(휴학·복학·학점·장학 등) 문장으로 Whisper를 파인튜닝하면 효과가 바로 보이고 전후 비교표를 만들기 좋음.

### 4-3. 역할 재분배 (제안, 팀 논의 필요)
| 팀 | 담당 | 제안 |
|---|---|---|
| 인식·속도 | STT 개선, 지연 측정 기준 | 이다혜 (파이프라인 담당) |
| 합성·목소리 | TTS 커스터마이징, 목소리 일관성 | 진주영 (치토 페르소나 설계 → 캐릭터와 목소리 일관) |
| RAG·데이터 | 코퍼스, 실시간 정보, RAG 전후 평가 | 박태연 (크롤러 담당) |

### 4-4. 참고
- 현재 로컬 테스트의 TTS는 `Qwen3-TTS-12Hz-1.7B-CustomVoice` **MLX 6bit**로, 3주차 벤치마크로 고른 **GGML Q8_0**과 실행 엔진·양자화가 다름. 로컬에서 나온 TTS 문제가 서버 환경에서도 똑같이 생긴다고 단정할 수 없음.
