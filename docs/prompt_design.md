# 프롬프트·페르소나 설계

담당: 진주영
현재 버전: **v2** (시스템 프롬프트, 최종) · 페르소나 한국어 v2.3 · 영어 v2.1 (최종)
관련 파일: `prompts/system_ko.md`, `system_en.md`, `user_turn.md`, `rewrite.md`, `persona_ko.md`, `persona_en.md`

---

## 1. 설계 요점

1. **근거 기반 생성:** 차별점은 "음성·다국어"가 아니라 "답변마다 근거, 없으면 안 지어냄". 시스템 프롬프트 최상단에 "가장 중요한 원칙"으로 배치.
2. **보류를 능력으로 설계:** "모르면 답하지 마"만으로는 안 지켜져서, 언제 보류할지 조건(A/B/C/D)과 보류 시 멘트 형식을 함께 규정.
3. **RAG 출처 주입 형식이 근거 표기를 좌우:** 검색 조각마다 `[출처: 문서명 | 조항/URL]`이 붙어야 모델이 그대로 인용하므로 server와 형식 합의 필요.
4. **출력이 음성(TTS):** 마크다운·목록·이모지·줄바꿈·괄호 금지, 묻는 것에만 최대 두 문장(80자 안팎, 약 12초 — v2. v1.4b는 조건이 갈리면 세 문장, 그 전에는 2~3문장 150자). 첫 문장에 출처와 답, 나열된 자료에서는 물은 것 하나만, 연락처는 물었을 때만. 근거 출처도 대시로 끝에 붙이지 않고 "…에 따르면"처럼 문장 앞에 녹임.
5. **다국어는 번역이 아닌 언어별 응답 생성:** 질문 언어 코드로 응답 언어 전환, 페르소나는 언어가 바뀌어도 유지.
6. **few-shot·CoT 절제:** 음성 파이프라인 지연 고려.

## 2. 근거 응답 규칙 (프롬프트가 반영, server가 1차 강제)

검색 신뢰도까지 포함한 4구간:

| 구간 | 상황 | 행동 |
|---|---|---|
| A. 근거 충분 | 질문에 대한 명확한 근거가 검색결과에 있음 | 답변 + 출처 |
| B. 근거 부분/조건 상이 | 관련 문서 있으나 학번 등으로 갈림 | 확인된 부분만, 갈리는 지점은 부서/포탈 안내 |
| C. 근거 없음 | 검색결과 무관/비어 있음 | 규정 생성 금지, 담당 부서 안내 |
| D. 범위 밖 | 실제 신청·개인정보 조회 | 처리 안 함, 학사서비스 포탈 연결 |

**정보 충돌:** 같은 항목이 다르면 상위·최신 문서 우선(학칙·학사요람 > 개별 안내 페이지).

**기본 안내처 (v2):** C·D 구간에서 검색결과에 맡은 부서가 없을 때만 쓴다. 모두 검색 자료에 실제로 나오는 부서다 (v1.4b까지 쓰던 '학사지원팀'은 자료 33개 어디에도 없었다). 부서 이름만 쓰고, 번호·위치는 검색결과에 있을 때만 말한다.

| 일 | 한국어 | 영어 (공식 이름은 유학생입학팀뿐, 나머지는 번역) |
|---|---|---|
| 학적·수업·휴학·복학·졸업·증명서 | 교무팀 (학과별 사항은 소속 단과대학 교학팀) | Academic Affairs Team (college's academic affairs office) |
| 등록금 납부·고지서 | 재무회계팀 | Finance and Accounting Team |
| 장학금 | 학생지원팀 | Student Support Team |
| 외국인 유학생 입학·체류·생활 | 국제협력처 유학생입학팀 | International Admission Office |
| 편의점·식당·주차 같은 시설 | 부서 이름 없이 학교 홈페이지 | the university website |
**평가 연결(eval/):** 근거 제시율(A·B), 무근거 회피율(C 함정 문항)로 측정 → 문항집에 함정 문항 배치.

## 3. 프롬프트 구조 (v1.1) — 멀티턴 + 시스템/사용자 턴 분리

### 왜 분리했나
v1은 시스템 프롬프트 하나에 역할·규칙과 질문·검색결과가 섞여 있었다. 실제 대화는 꼬리질문("그럼 휴학은?")과 형태 변경 요청("방금 답 영어로")으로 이어지는데, 이 구조로는 (1) 팔로업이 검색되지 않고 (2) 대화 기억만으로 답해 무근거 생성이 샌다. → **고정(시스템) / 가변(사용자 턴)**을 분리하고 RAG 앞에 **질문 재작성** 단계를 둔다.

### 한 턴 처리 흐름
```
음성 입력
  → STT (텍스트 + 언어코드)
  → [rewrite.md] 팔로업이면 앞 맥락 합쳐 '독립 질문'으로 재작성
        · 형태만 바꾸는 요청이면 [NO_SEARCH] 반환
  → (NO_SEARCH가 아니면) RAG 검색 → 검색결과
  → [user_turn.md] 최근 대화 + (재작성된) 현재 질문 + 검색결과 조립
  → LLM 호출: system_ko/en.md(고정) + user_turn(이번 턴)
  → 답변 → TTS → 음성 출력
```

### 파일 역할
| 파일 | 성격 | 내용 |
|---|---|---|
| system_ko/en.md | 고정(매 턴 동일) | **무엇을 말할지**: 역할·근거 원칙·답변 판단(A/B/C/D)·멀티턴 규칙·근거 표기·음성 형식·금지 |
| persona_ko/en.md | 고정(시스템 뒤에 `<persona>`로 붙음) | **어떻게 말할지**: 정체성·성격·말투·응답 예시. 충돌 시 system이 우선. `persona_ko.md`의 TTS 블록(목소리 설정)은 LLM에 보내지 않음 |
| user_turn.md | 가변(매 턴 교체) | <대화기록> + <현재질문> + <검색결과> |
| rewrite.md | RAG 앞단 | 팔로업 → 독립 질문, 형태 변경 요청 → [NO_SEARCH] |

### 멀티턴 규칙 요약
- 사실 팔로업도 **그 턴의 검색결과에 근거**해 답한다(대화 기억만으로 규정 답변 금지).
- **형태만 바꾸는 요청**(영어로/짧게/다시)은 재검색 없이 직전 답을 변형만 한다 → 보류 규칙(C)의 유일한 예외.
- 히스토리는 **최근 2~3턴**만(음성이라 지연·토큰 억제). 넘치면 요약.
- 언어는 매 턴 감지, 페르소나 유지.

## 4. 프롬프트 계약

**① 근거 규칙 강제 위치 → server + 프롬프트 이중**
- server(태연/다혜): 검색결과가 비었거나 신뢰도 점수가 임계값 미만이면 LLM에 넘기지 말고 정형 보류 응답으로 1차 차단한다(무근거 회피율 100% 보장). 게이트에서는 질문 영역을 모르므로 v2부터 부서 이름 대신 "학사서비스 포탈이나 학교 홈페이지"로 안내한다 (`server/gate.py`).
- server: 위기 발화("죽고 싶어" 등)는 게이트·검색보다 먼저 잡아 고정 상담 안내로 답한다 (`server/crisis.py`, 11/3). 인사·잡담·감정 표현·빈말은 검색 없이 잡담 경로로 보낸다 (`server/smalltalk.py`).
- 프롬프트: 게이트를 통과한 회색지대(근거 애매·조건 상이)만 판단한다. → <검색결과>에는 게이트 통과분만 들어온다는 전제로 유지.

**② RAG 출력 형식 → 아래 형식으로 고정**
```
[출처: 문서명 | 조항/URL] 본문 (점수: 0.87)
```
- 문서명은 소리내 읽기 자연스러운 이름으로(예: `bulletin_2024.pdf`가 아니라 `학사요람 2024`).
- 신뢰도 점수를 함께 싣는다. → ①의 server 게이트가 이 점수를 임계값 판단에 쓴다.
- 이 형식이 프롬프트의 근거 인용을 좌우하므로 변경 시 반드시 사전 공유.

**③ 검색결과 주입 위치 → 사용자 턴**
- 시스템 프롬프트(`system_ko/en.md`)는 고정으로 두고, 질문·검색결과·히스토리는 `user_turn.md` 형태로 매 턴 '사용자 메시지'에 주입한다.
- 시스템 프롬프트 안에 검색결과를 섞지 않는다(캐싱·유지보수 목적).

**④ 멀티턴 처리 → 아래대로 구현**
- RAG 검색 전에 `rewrite.md`를 호출해 팔로업을 독립 질문으로 재작성한다.
- 재작성 결과가 `[NO_SEARCH]`면 검색을 건너뛰고, 직전 답 변형 요청으로 처리(<검색결과> 비움).
- 사실 질의는 매 턴 재검색한다(대화 기억만으로 규정 답변 금지).
- 히스토리는 최근 2~3턴만 `user_turn.md`의 <대화기록>에 전달한다.

**주입 계약(자리표시자)**
| 자리표시자 | 값 | 담당 |
|---|---|---|
| {{LANG}} | STT 감지 언어(ko/en) | 파이프라인(다혜) |
| {{CURRENT_QUESTION}} | 재작성된(또는 원문) 현재 질문 | rewrite 단계 |
| {{RETRIEVED_CONTEXT}} | RAG 결과, `[출처: 문서명 | 조항/URL] (점수)` | RAG server(태연) |
| {{RECENT_HISTORY}} | 최근 2~3턴 | 파이프라인(다혜) |

## 5. 향후 개선 메모

- 근거 표기 few-shot 예시 1~2개 추가(지연 고려 최소화). — 하지 않음 (v2가 최종)
- 질문 영역 → 담당 부서/연락처 매핑표를 코퍼스에서 뽑아 부착 → 보류 멘트 정확도 향상. — v2 '기본 안내처'로 반영 (부서 이름만, 연락처는 검색결과에서)
- 재작성 품질은 파이프라인 연결 후 실제 대화로 점검. — 스모크 M1에서 같은 꼬리질문의 재작성이 실행마다 달라지는 것을 봄 (절차만 묻는 질문으로 바뀌면 규정을 빠뜨림). 재작성 프롬프트는 v2에서 바꾸지 않았다.
- v2 이후 프롬프트·페르소나는 고치지 않는다 (11/3 결정). 남은 오답은 검색·자료 쪽이다 (`docs/eval_100_ko_en.md` 8절).
